# LC 15 — 3Sum

**Pattern:** Two pointers (after sort)  
**Difficulty:** Medium  
**Code:** [`ThreeSum.java`](../../../src/main/java/ThreeSum.java)

---

## Problem

Given an integer array `nums`, return all unique triplets `[a, b, c]` such that `a + b + c == 0`.

**Constraints / edges worth remembering**
- Triplets must be unique (no duplicate sets).
- Array can be empty or have fewer than 3 elements → empty result.
- Duplicates in input are common; sorting makes them easy to skip (or dedupe via a set).

---

## Intuition

Sort first. Fix one number `nums[i]`, then the rest is classic 2Sum on the right side with two pointers. Sorting turns “find pair summing to `-nums[i]`” into an O(n) scan and clusters duplicates together.

---

## Approach

1. Sort `nums`.
2. For each index `i` from `0` to `n - 3`:
   - Set `j = i + 1`, `k = n - 1`.
   - While `j < k`, compare `nums[i] + nums[j] + nums[k]` to 0 and move pointers.
3. Collect unique triplets (your code uses a `HashSet` of lists; interview version usually skips duplicate `i`/`j`/`k` explicitly).

---

## Solution sketch

```java
Arrays.sort(nums);
for (int i = 0; i < n - 2; i++) {
    int j = i + 1, k = n - 1;
    while (j < k) {
        int sum = nums[i] + nums[j] + nums[k];
        if (sum == 0) { /* add triplet */; j++; k--; }
        else if (sum < 0) j++;
        else k--;
    }
}
```

---

## Complexity

| | |
|---|---|
| **Time** | O(n²) — sort O(n log n) + for each `i`, two-pointer O(n) |
| **Space** | O(1) extra beyond output if skipping duplicates in-place; O(n) if using a set of triplets |

---

## Variations

| Variant | Change in approach |
|---|---|
| **2Sum** | Hash map or two pointers on sorted array |
| **3Sum Closest** | Same skeleton; track best `|sum - target|` |
| **4Sum** | Fix two indices, then two-pointer; O(n³) |
| **3Sum With Multiplicity** ([`ThreeSumWithMultiplicity.java`](../../../src/main/java/ThreeSumWithMultiplicity.java)) | Count combinations with freq map + nCr cases instead of listing triplets |
| **3Sum smaller** | Same two pointers; when `sum < target`, all `k` in range count |

---

## Pitfalls

- Forgetting uniqueness → duplicate triplets.
- Not sorting → two-pointer invariant breaks.
- Moving only one pointer on a hit → misses or duplicates pairs.
- Your set-of-lists version is correct but uses more memory; interviewers often want the skip-duplicates style.
